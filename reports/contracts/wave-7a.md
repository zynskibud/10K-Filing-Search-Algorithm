## Rules
- LIGHT: all tests use `FakeLLMClient`. No Ollama calls. No corpus reads beyond fixtures.
- No commits.

## Deliverables
1. `context.py`: small-to-big assembly. Input: the reranked top-k `Result`s. Group by `section_id`; fetch each section's full text from the `sections` table, and for table chunks the full table text from `tables_parsed`; order groups by best rank; assign each group a chunk id list. Budget: total context at most 20,000 tokens (bge-small tokenizer as the ruler, same as chunking). If one section exceeds 4,000 tokens, send a window of the section: the paragraphs around the matched chunks up to 4,000 tokens, with `[...]` marks. Stop adding groups when the budget is reached. Returns `ContextBlock`s: `{ref: int, chunk_ids: [...], section_id, accession_no, company, fiscal_year, item, section_title, page_start, page_end, text}`.
2. `prompt.py`: `evals/prompts/answer.v1.md` and a builder. The prompt: instructions (answer only from the blocks; cite with `[ref]`; give the exact quote for each citation; if the blocks do not contain the answer, say "The filings do not contain this information." and cite nothing; be short), then the blocks as `[1] Company | FY | Item | section title | pages a-b` followed by the text, then the question. Output format: JSON with `answer` (prose with `[n]` markers), `citations`: list of `{ref, quote}`, `answerable`: bool.
3. `llm.py`: `OllamaChat(model="qwen3:8b", thinking: bool, temperature=0, num_ctx=32768, timeout=900)` through the Ollama chat API with `format: "json"` for the final answer; the `think` option toggles thinking (Ollama supports `"think": false`); records input and output token counts and wall time from the response fields. `FakeLLMClient` returns canned JSON. Reuse the client class from `citation_rag/search/router.py` if it already exists there (import it); otherwise define it here and leave a note for the orchestrator.
4. `cite.py`: citation check in code. For each citation: the `ref` exists in the sent blocks; the `quote` (whitespace-normalized) is a substring of that block's text; map the ref to `{accession_no, company, fiscal_year, item, section_title, page_start, page_end, chunk_ids}`. Each `[n]` marker in the answer must have a citation entry. Results: `valid`, `invalid_refs`, `unquoted_markers`, `quotes_not_found`. An answer with `answerable=false` must have zero citations; otherwise flag `refused_with_citations`.
5. `pipeline.py`: `answer(question, config) -> AnswerRecord`: router (mode from config: `oracle` with a golden case, or `llm`), retriever (wave 5a), optional reranker (wave 6), context, prompt, LLM, citation check. Writes one row to `run_log` (schema in `citation_rag/index/schema.py`) with every id list, the context token count, the answer, the citations, model, thinking flag, and per-stage latency. Config also has `mode`: `rag` (run B) or `no_docs` (run A: the prompt has no blocks and asks the model to answer from its own knowledge or say it does not know; citations are not required).
6. `run_all.py`: `--split dev --runs A_think A_nothink B_think B_nothink --config <winner json>` runs each configuration over the dev golden set, writes answers to `evals/answers/{run_name}.jsonl` (question id, answer JSON, citation check, run_log id, latencies), and prints per-run counts (answered, refused, citation-valid share) without any judge call. `--dry-run` prints the plan. Judge scoring is a separate command in `citation_rag/evals/judge.py` (exists) invoked in wave 7 after calibration.
7. Tests (all with fakes): context budget respected and window logic on a long fixture section; prompt contains every block header; citation check on valid, invalid ref, quote not found, marker without citation, refusal with citations; pipeline end to end on the fixture corpus with the fake LLM, producing a run_log row in a throwaway schema; run_all dry run.

## Definition of done
- `uv run pytest tests/test_answer.py` passes.
- `uv run python -m citation_rag.answer.run_all --dry-run` prints the four runs.
