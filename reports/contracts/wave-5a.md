# Wave 5a contract: search code (BM25, vector, hybrid, routing)

LIGHT build task (Sonnet). Owns `citation_rag/search/`, `tests/test_search.py`. Depends on schema section 4 (chunk columns) and the harness interface in `citation_rag/evals/runner.py` (`Result` and the retriever callable). Plan: Plan tab section 8.

## Rules
- LIGHT: unit tests on a fixture of about 200 chunks with random or CPU-computed vectors. No Ollama calls in tests (the router has a fake client). No corpus-scale runs.
- The retrieval experiments in wave 5 must run without the GPU. So: query embedding on CPU is allowed (100 questions, bge-small or bge-m3 on CPU is seconds to minutes), and routing has two modes: `oracle` (use the golden case's `companies`) and `llm` (Qwen through Ollama, GPU class, wave 7). Experiments A, B, C use `oracle`. The router's own accuracy is measured in wave 7.

## Deliverables
1. `bm25.py`: own implementation. Tokenizer: lowercase, split on non-alphanumerics, keep tokens of length >= 2 and all numbers, no stemming, English stopword list of about 50 words removed. Index: `build(index_name, rows)` from the chunk table (`id`, `embed_text`) into an inverted index with document frequencies and lengths; `k1 = 1.5`, `b = 0.75`; `search(query, k, filter_ids=None) -> [(id, score)]`. Persist with pickle to `data/bm25/{index_name}.pkl`, load lazily. About 100 lines. Filtering by company: the caller passes the allowed chunk ids (from a SQL query on cik), or the index keeps a `cik` per id and `search(..., ciks=[...])` filters during scoring.
2. `vector.py`: `search(index_name, qvec, k, ciks=None, ef_search=100) -> [(id, distance)]` with `SET LOCAL hnsw.ef_search = %s` and `WHERE cik = ANY(%s)` when filtered, ordered by `embedding <=> %s`. `exact_search(...)` with `SET LOCAL enable_indexscan = off; SET LOCAL enable_bitmapscan = off` for the recall check. Uses one psycopg connection pool from settings.
3. `fusion.py`: `rrf(lists, k=60) -> [(id, score)]`. Also `weighted_sum` is NOT implemented (RRF only, per plan).
4. `router.py`: `Router` protocol with `route(question) -> {"companies": [cik...] | "general", "unresolved": [names]}`. `OracleRouter(case)` returns the golden companies. `LLMRouter(client)` builds the prompt (list of corpus companies with tickers is too long for the prompt; instead: extract candidate names and tickers from the question with the LLM, then match them to `filings` by exact ticker or normalized name with a small alias table, returning unresolved names). JSON output. `FakeLLMClient` for tests. `OllamaClient` implemented but never called in tests.
5. `retriever.py`: `Retriever(index_name, method, k=50, top=8, ef_search=100, per_company_top=4, general_cap=2, router=...)`. `__call__(question, companies=None) -> list[Result]` matching the harness. Steps: route (or use the provided companies), then for each named company: BM25 and/or vector search filtered to that cik, RRF when hybrid, keep `per_company_top` after fusion (reranking is added in wave 6 as an optional step between fusion and the cut); for `general`: unfiltered search, then cap per cik. Returns `Result` objects with text, token_count, section_id, table_id, pages, accession_no. Each result also carries `scores` (bm25, vector, rrf) for the log.
6. `experiments.py`: `--exp A` runs the 7 indexes x 3 methods on the dev split with `oracle` routing, through `citation_rag.evals.runner.run_eval`, config recorded, and prints the comparison table from `evals.report`. `--exp hnsw` runs the exact-vs-HNSW recall check on one index at ef_search 40, 100, 200 (100 dev questions, recall of HNSW top-50 against exact top-50, and latency). Nothing in this file runs in this wave beyond `--dry-run`, which prints the run matrix.
7. Tests: BM25 scoring on a tiny corpus with hand-computed expectations (IDF and length normalization), filter correctness, RRF on the worked example from the plan (chunk A ranks first), the retriever end to end on the 200-chunk fixture loaded into schema `test_wave5` (create and drop) with oracle routing, the per-company loop (two companies, budget respected), the general cap, and the LLM router with the fake client on 6 questions covering the four edge cases (ticker, full name, unknown company flagged, vague, none, two companies).

## Definition of done
- `uv run pytest tests/test_search.py` passes.
- `uv run python -m citation_rag.search.experiments --exp A --dry-run` prints the 21-run matrix.
